# FTK Mod Framework 1.2.0

Framework 1.2.0 adds combat action capabilities used by the separately versioned
Paladin 1.3.0 overhaul. Install the matching framework and launcher helper before
using packages that declare these capabilities. Existing class, race, Thief,
reporting, and Cleansing March support is retained.

- Registered classes and equipped nonweapon equipment can grant native rolling
  combat actions. Backpack items grant nothing, duplicate grants share one
  button, and equipment cards list their granted actions.
- Registered armor/resistance debuff variants can share an equally weighted
  choice tied to synchronized combat action identity. The selected outcome uses
  the existing native attack message and does not advance native RNG.
- Magic actions can receive an explicit damage multiplier against an active
  resistance debuff from specific registered source actions. Native expiry and
  removal end eligibility; the debuff is not consumed.
- Explicit custom descriptions survive the native Standard Attack tooltip
  fallback for non-perfect actions without a status prefab.

Paladin 1.3.0 uses these features for Censure on its hammers and Smite on its
trinkets. Guard and Cleansing March remain class features. Mod authors can read
[class and equipment actions](../COMBAT-PROFICIENCIES.md) for API, JSON, and
validation details.

The updater accepts compatible framework installations from 0.1.0 up to, but
not including, 1.2.0 on the existing verified macOS game fingerprint. It still
checks exact game and managed-package compatibility and replaces the framework
and helper together. No additional game build is claimed supported.

Game-free checks cover registrations, equipped-only grants, deterministic branch
selection, source-qualified damage, UI descriptions, and rollback. All four
platform launcher bundles build successfully, including the Windows launcher
cross-build, and their packaged framework/helper hashes match their manifests.
These checks do not execute the Windows launcher or installer. Live co-op,
new-capability hot activation, and Windows/Linux gameplay remain unverified.
Use a full game restart after changing content that declares the new capabilities.
Windows x64 bundles remain a preview; Linux arm64 supports helper tooling rather
than a native ARM game port. The macOS launcher is not notarized, so Gatekeeper
may require right-click > Open. Release assets contain no game assemblies.

The [verification receipt](../evidence/framework-1.2.0-verification.md) records
the tested DLL hash, game-free results, fresh-process native smoke, and remaining
coverage limits.
