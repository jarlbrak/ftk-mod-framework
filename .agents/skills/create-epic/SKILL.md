# Create epic

1. Read root instructions, roadmap, open issues, and `.github/ISSUE_TEMPLATE/epic.md`.
2. Confirm the problem, player/mod-author value, scope boundary, success measures, and non-goals.
3. Consult the architect role for consequential architecture and the game-designer role for content
   direction. Use same-session role application if delegation is unavailable.
4. Draft one epic with an executive summary, goals, success metrics, constraints, risks,
   dependencies, proposed spec breakdown, and explicit evidence expectations.
5. Search for duplicates before creating anything.
6. Show the proposed title/body and stop for user confirmation before the external GitHub write
   unless the request already explicitly authorized creation.
7. Verify the created issue, labels, and references after mutation.

Private knowledge may inform discovery but must not appear as a required public dependency.
