# Compare approaches

1. Define the decision, constraints, source evidence, and non-negotiable invariants.
2. Compare each approach on correctness, public API impact, deterministic behavior, failure safety,
   net35 feasibility, validation cost, migration/recovery, and conceptual complexity.
3. Reject approaches that rely on unverified game assumptions before scoring convenience.
4. Recommend one direction and the smallest steel-thread experiment that tests its riskiest premise.

Do not manufacture balance by listing symmetrical pros and cons when one option is clearly safer.
