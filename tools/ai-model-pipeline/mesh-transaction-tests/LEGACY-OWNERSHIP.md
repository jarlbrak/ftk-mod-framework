# Legacy visual ownership boundary

The singular public GLB API keeps its existing renderer selection, permissive three-argument decoder, skeleton rebind, and AssetBundle fallback. The allocated GLB mesh now enters an `EnemyMeshResources` lease before assignment. Optional PNG preparation is a separate transaction: missing files, exceptions, and `LoadImage == false` leave the mesh applied and prior material appearance intact, except when a renderer rollback itself fails. Treating a false decode as a logged optional failure is an intentional narrow correction.

Tint and optional texture changes explicitly copy non-null `sharedMaterials` slots. Copies enter the lease before renderer assignment; inherited materials are never treated as exclusive. Null slots and ordering are preserved. Bundle meshes and textures remain shared cached assets; the framework leases only the material copies it creates around them.

`VisualResourcesOnly` distinguishes successful legacy/tint resource ownership from a completed explicit renderer plan. Existing serialized owners default to false. A resource-only flag is insufficient: the real lease must be acquired, registered, and live. A later explicit enemy or player plan must perform its normal validation and transaction; only full success clears the flag. Appending allocations preserves the prior lease, owner count, renderer targets, and scrolling provenance. A successful rollback removes only the new batch. If renderer restoration fails, the batch remains leased until final owner release and an error records that cleanup is uncertain; the failed plan is not marked complete.

Exact native `ScrollingUVs` layouts can use the existing narrow prefix with explicitly registered private material provenance. Invalid indices/properties, null slots, and unsupported component types remain native, with no prefix phase update. Subsequent native getter-created materials in those unsupported layouts are outside this ownership guarantee. This is not a general material allocation hook.

The actual-source linked tests exercise ownership and transaction decisions against Unity boundary stand-ins. They cover native-equivalent prefix phase arithmetic while enabled/disabled, explicit source/clone/grandclone material copies, invalid layout rejection before phase, tint-to-explicit success and rollback, missing real lease, optional PNG failure, and retention of an uncertain rollback batch until final release. They do not establish Unity native lifecycle, real public-loader/HUD cloning, never-active automatic owner acquisition, or final Diorama disposal. Those remain separate isolated live gates. No test manually disposing a transferred lease asset counts as native disposal proof.
