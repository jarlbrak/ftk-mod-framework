# Street Twins original art candidate

Street Twins is a matched pair of broad working daggers, with dark leather
grips, slate teal repair binding, brass guards and bright faceted steel edges. `build.py` authors every surface and color. No native surface data,
commercial asset or generated concept image supplies the design. The icon is a
render of the same original geometry.

This directory contains an offline candidate. It does not establish in-game
fitting, either hand's motion, card framing, resource lifetime or art acceptance.
The package uses explicit `offHandModels` assignments for the second blade.
Do not publish this candidate as finished.

## Reproduce

From the repository root, with Blender on PATH and a Python environment containing
NumPy, Pillow and UnityPy:

```sh
python art-experiments/thief/inspect_native_route.py --assets "$FTK_DATA/resources.assets" --assembly "$FTK_DATA/Managed/Assembly-CSharp.dll"
blender --background --python art-experiments/thief/build.py
python art-experiments/thief/validate.py
git diff --check
```

`FTK_DATA` must point to the explicitly configured, read-only source installation.
Asset generation itself consumes the checked metadata JSON and needs no game
files. The inventory script reads only GameObject, Transform, MeshFilter and
MeshRenderer metadata. It never dereferences native mesh or texture pointers.
`native-route.json` pins the source asset and assembly hashes.

The generator calls the project's strict static GLB writer and original source
icon renderer. Editable geometry arrays, per-component triangle maps, source
hashes and output hashes accompany every GLB. `validation.json` is generated by
the independent validator. Packaged copies and provenance live under
`marketplace/packages/thief/assets/`.

## Native paired route

Fresh metadata inspection of `resources.assets` finds these paths relative to
the whole item/display prefab:

| Template | Display root | Main renderer | Off-hand renderer | Break renderers |
| --- | ---: | --- | --- | --- |
| `dualKnife` | 32973 | `dualKnife`, 101925 | `offHandWeapon`, 101774 | `dualKnife/Break`, 101826; `dualKnife/Break/Break`, 101859 |
| `dualDagger` | 36256 | `dualDagger`, 101500 | `offHandWeapon`, 101688 | `dualDagger/Break`, 101982; `dualDagger/Break/Break`, 103140 |

All four renderer objects per template have exactly one MeshRenderer, MeshFilter
and material pointer. The paired sibling has no Weapon component. The main
Weapon GameObjects are 43859 and 48358, respectively. Exact local transforms are
recorded in `native-route.json`; no native vertices or bounds were inspected.

Installed-assembly inspection of `FTKHub.CreateWeapon(FTK_itembase.ID)` shows that
it clones the item prefab, detaches its Weapon child, schedules the prefab parent
for destruction, resets Weapon scale to one and returns the Weapon GameObject.
Consequently, item model paths on this returned root are `.`, `Break`, and
`Break/Break`. `offHandWeapon` is outside that root. The package addresses the detached sibling through its separate
`offHandModels` assignment; a main-hand child path cannot reach it.

`CharacterEventListener.AssignWeapon` separately reparents `Weapon.m_OffHand` to
the opposite holder, with zero position, Euler rotation `(0,180,180)` and unit
scale. `Weapon.GetOffHandWeaponHolder` maps the normal `WEAPON_HOLDER` to
`WEAPON_HOLDER_L`. `Weapon.Break` recursively detaches the break hierarchy. These
are source-backed behavior findings. Live review and its limits are recorded
separately in the review directory.

## Candidate binding map

These assets target `dualKnife`; sharing the inspected break transform with
`dualDagger` does not establish another equipped/display fit.

| Surface | Root/path | Asset |
| --- | --- | --- |
| Main hand | returned Weapon, `.` | `thief-street-twins.glb` |
| Off hand | explicit off-hand object root, `.` | `thief-street-twins.glb` |
| Blade fragment | returned Weapon, `Break` | `thief-street-twins-fragment-1.glb` |
| Handle fragment | returned Weapon, `Break/Break` | `thief-street-twins-fragment-2.glb` |
| Display main blade | whole display prefab, `dualKnife` | `thief-street-twins-display.glb` |
| Display paired blade | whole display prefab, `offHandWeapon` | `thief-street-twins-display-offhand.glb` |
| Palette | every replacement renderer | `thief-street-palette.png` |
| Inventory icon | one combined pair identity | `thief-street-twins-icon.png` |

The fragment files are converted into their actual child-local spaces. Together
they reconstruct the original blade and grip exactly once under those native
transforms. Display files invert each actual display-child transform around an
original splayed-pair composition. Its size comes from authored landmarks, not
native mesh bounds. Card fit remains a live gate. The display break objects stay
inactive under the native Weapon initialization; any runtime path that shows
them requires its own observation and explicit replacement decision.

The revised dagger measures 0.709 authored units from pommel to tip, with the
hand grip center near the origin. The equipped export applies a `Z55 @ Y90`
rotation to bring the cutting face into view and tip the blade down from the
native forward-facing mount. The item display and icon undo that equipped
rotation before arranging the pair. All fragments reconstruct the equipped
geometry. Native hand contact and motion require their own review.
