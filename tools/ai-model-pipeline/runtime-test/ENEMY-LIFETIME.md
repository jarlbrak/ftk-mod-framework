# Passive public enemy / native HUD resource lifetime

This helper observes actual public-bound combat CELs passed by native `uiActiveTime.FillPortraitTextures` to the avatar Snapshot overload. It does not construct UI/avatars, render, acquire a lease, invoke cleanup, modify materials, or change game actions. This is separate from the synthetic no-CEL material-lifecycle fixture and the constructed native row-preview fixture.

At strict native Ready, before the selected encounter and with no portrait/arrival watch active, arm:

```json
{"id":"NEW_32_HEX_ID","session":"CURRENT_NONCE","op":"enemy-lifetime-watch","enemy":"EXACT_PROFILE_KEY","catalogSha256":"EXACT_CATALOG_SHA256","bindingKind":"legacy-singular"}
```

`bindingKind` may instead be `explicit-plural`. It is an expectation checked against the actual registered Core `EnemyVisual`, not evidence supplied by the caller. Nonempty `rendererMeshes` always classifies as plural even if `glbMesh` is also set. Plural descriptor paths/GLB/PNG/emission/material-slot fields are compared to profile metadata and pinned. A singular fixture requires actual empty plural assignments and matching registered `glbMesh`/`glbTexture`, one metadata renderer, explicit `bindingKind` and tint RGBA, matching optional visualScale, no bundle/procedural/lantern/aura/wet/deformation/weapon options and no native scroller. The content plugin must genuinely call the singular API. A profile renderer description alone cannot establish that API path.

The singular observer uses the same source-audited selection rule: the first exact `enTroll01` transform's SMR, otherwise the first SMR below the CEL. The selected actual renderer must match the metadata path. `Applied`, `VisualResourcesOnly`, real `_acquired` state, registered owner/refcount/resource sets and target references are separate evidence. Tint can set Applied before a singular mesh load; that flag alone never proves body success. The actual custom mesh name and resource membership, remapped bones, assigned material ownership and optional texture membership are reported. Missing optional PNG remains nonfatal: raw texture membership is not a pixel/content proof. Material `_Color` and `_EmissionColor` values are measured, but no automatic tint appearance verdict is produced.

The watcher pins root, nonce, Core/helper/content/native assembly identities and on-disk hashes, loaded catalog equality, every requested GLB and PNG including secondary material slots, actual registration and original native prefab. Full disk pins are rechecked at native attribution and explicit readout; per-frame samples state that they do not rehash all files every frame. Hashes describe measured files, not a hash of loaded process memory.

Native observations are:

1. Before native InstantiateTarget: exact combat dummy/FID/reciprocal CEL plus source owner, complete source lease/refcount/owner set and owned resource union.
2. Before native DoRender: actual cloned CEL/owner/targets/bones, acquired membership in the same lease and exact source owner set plus the new clone. Additional unexplained ownership fails attribution. Shared mesh/texture IDs and any naturally created private material union remain explicit.
3. Native Snapshot finalizer: unchanged native exception, target/texture-pointer cleanup state, and source measured-field comparison. Lease metadata is excluded from source invariance because the legitimate clone borrow changes it. Original prefab invariance is checked separately. These comparisons cover only emitted transforms/reference/controller fields, not every shader property.
4. Subsequent helper frames and explicit `enemy-lifetime-state`: actual Unity-null owner/CEL/resource wrappers, raw lease absence/refcounts, observed Diorama cleanup membership, source liveness, native HUD texture dictionary/FID and active RawImage joins. The HUD-generated texture, native cached camera/RenderTexture and native prefab resources are separate from the model resource union.

Normal combat may leave the source CEL in native `m_DioramaCleanup`. Ready, an empty enemy map, UI disappearance or zero HP does not prove final disposal. Keep reading until separately authorized native cleanup actually removes the final owner and every pinned leased resource becomes Unity-null. The observer never calls Retain, Release, Destroy, prune or native cleanup to obtain a pass.

Commands `enemy-lifetime-state` and `enemy-lifetime-clear` take only the normal id/session/op envelope. Clear drops bounded managed references and stops this watch; it does not destroy native objects. Preserve results before clear. Existing armed resource readout may continue after a DB row-reference replacement if the original root/nonce/Core/catalog/assets remain pinned; new source attribution stops permanently. Changed binary/catalog/asset/root/session pins permanently invalidate further observation, even if files are later restored; readout retains only prior evidence and its frame. Diagnostic history or measured-source errors alone do not close that identity gate. Diagnostic errors remain permanent and cannot later become a successful report.

Limits: 8 owner records, 8 leases, 256 resource wrappers including native references, 8 HUD snapshots, 512 change records, 64 live renderer records and 16 materials per renderer. Saturation stops new attribution and marks history incomplete, while fresh known-resource readout remains available with its exact frame. This avoids losing final-disposal evidence merely because a history buffer is full. Unknown/destroyed owners first encountered after the fact, ID collisions, unaccounted owner/resource changes and partial failures remain explicit errors.

Offline validation uses 59 linked shipped-Newtonsoft policy/pin assertions and four boundary checks and static no-mutation boundaries. The [first singular live trial](../../../docs/evidence/legacy-singular-native-hud-lifetime-v1/README.md) independently verifies actual native HUD acquisition, clone-first release and final source/owned-resource disposal with Core `c7684e91` and helper `ac9b0278`. Native assets survive; the HUD output texture is released while the native camera/render-texture cache remains. The fish body's `matLoot` name excludes it from tinting, so this does not prove the combined tint-and-mesh path. Never-active native acquisition, source-first survivor destruction, arbitrary clone/grandclone behavior, failed renderer commits and all-process leak freedom are not inferred. Deliberately deploy and pin the reviewed Core/helper for a new trial. Existing plural catalog-preflight is not silently repurposed to certify a legacy registration.
