# Equipment Exchange

Unreleased source candidate. Not published or gameplay-approved. The candidate requires the framework changes in this checkout; its manifest version is not a claim of public availability.

Guild Tokens are a shared equipment currency for every class. Their inventory icon is an original faceted merchant medallion with a coin-purse emblem. Paladin is the first catalog contributor; the currency is not a Paladin item and does not require a Paladin in the party.

The prototype awards one party-loot token on a 10% ordinary or 50% reviewed named-boss roll for an eligible native displayed-level-8-plus enemy. A shared counter guarantees a token on the sixth consecutive eligible opportunity after five misses. The boss chance replaces the ordinary chance. Native drop eligibility and reviewed multipart boss groups still apply. The safeguard makes effective supply higher than the base percentage; campaign pacing is not yet accepted.

Class packages register their chosen equipment with the same `equipment_token` currency through `townExchange`. Every native town exposes Back Alley in the native vendor interface, including item models and equipped comparisons. Stock shows only offers registered for the buying character's class and hides items that character already owns in their backpack or equipment. A purchased piece disappears immediately. Class and ownership are checked again at confirmation and before any token debit, so stale menus cannot buy a duplicate or another class's piece. Tokens remain universal and can be transferred normally. The currency badge shows the current character's tokens. Buy opens a native confirmation; delivery is to the backpack for normal inventory equipping. One owned token buys one selected piece after confirmation; completed purchases cannot be refunded for tokens. The current transaction implementation permits solo purchases only. Online purchases remain disabled pending a verified authoritative transaction path.

Framework 1.7.0 incorporates this service. This directory is retained as an unpublished legacy compatibility fixture, not a second player installation path. New class and equipment packages contribute catalogs to the framework and do not depend on this package. Existing development installs are deduplicated by the reserved token identity; final save and install migration still require native validation.

The ordinary drop/shop settings on the token itself are disabled: only the registered reward rule grants it. Exclusive vendor items are filtered from ordinary shops and native loot, including existing merchant stock. Owned gear is preserved. A bounded isolated single-player test has exercised one earned token, native collection and transfer, a historical cross-class Thief purchase (superseded by class filtering), cancellation, insufficient-token blocking, native equipping, ordinary-market restoration and save/resume. This does not establish campaign supply, named-boss odds, combined catalogs, every city, co-op or release readiness.

Website impact: at release, describe the built-in service and catalog-contributing packages in the universal currency guide and Paladin acquisition pages; regenerate published item data. Do not add a separate installable Exchange library entry. Current published site data is unchanged.
