# Create spec

1. Read the parent epic, related code/docs/issues, root instructions, and spec template.
2. Establish current behavior from repository and game-source evidence, not assumptions.
3. Define functional requirements, non-functional constraints, affected boundaries, failure
   behavior, deterministic/save/co-op impact, and proof plan.
4. Get architecture review before finalizing a non-trivial boundary or public API.
5. Split work into independently verifiable work items with explicit ordering and dependencies.
6. Search for overlap, present the draft, and require confirmation before creating the issue unless
   creation was explicitly authorized.
7. Verify exact `Parent epic: #N` linkage, labels, and acceptance criteria after creation.
